ЧАСТЬ A. ЧТО УЖЕ РЕАЛИЗОВАНО
--------------------------------------------------------------------------------

A1. Цель MVP (достигнута)
-------------------------
Владелец/управляющий после входа по PIN может открыть карточку занятой
студии и скачать операционный черновик договора аренды в PDF с кириллицей,
описью и пометкой «для внутренней работы».


A2. Зависимости и шрифты
------------------------

[DONE] db/fonts/Roboto-Bold.ttf
[DONE] Путь к шрифтам: fileURLToPath(new URL('./fonts/...', import.meta.url))
      в db/pdf-builders.mjs


A3. Контур X-Florens-Token
--------------------------
Сервер (db/http.mjs):
[DONE] POST /api/auth/session
       тело: { staffId, pin, role? }
       сверка PIN с KV salam-residences-staff + seed-аккаунты (DEMO_PIN)
       выдача crypto.randomUUID(), хранение сессий в Map в памяти процесса
[DONE] POST /api/auth/logout — сброс токена по заголовку
[DONE] requirePdfAuth(req, res):
       — нет/битый токен → 401
       — роль crew → 403
[DONE] CORS: Access-Control-Allow-Headers включает X-Florens-Token

Клиент:
[DONE] src/florensToken.js — get/set/clear, sessionStorage ключ florens-token,
       requestFlorensSession, revokeFlorensSession
[DONE] src/ui/Auth.jsx — после login / owner / join: flushPersist + запрос токена
       (для crew токен не запрашивается)
[DONE] src/app/store.jsx — logout вызывает revokeFlorensSession


A4. Билдер договора
-------------------
[DONE] db/seed-catalog.mjs — серверное зеркало учебного фонда 35 студий
       (seed живёт в domain.js на клиенте, в KV units нет — без каталога
       студия 201 на сервере была бы недоступна)
[DONE] db/pdf-builders.mjs

       — таблица описи
       — пометка «Операционный черновик (для внутренней работы)»

================================================================================
УЛУЧШЕНИЕ U1. Folio PDF (лицевой счёт)
Приоритет: высокий | Оценка: 0.5–1 день
================================================================================

Цель
----
С карточки студии (и опционально жильца) скачать PDF с оборотами stay:
залог, начисления аренды, оплаты, коммуналка (газ/свет/вода), итог долга.

Контекст данных
---------------
Клиент уже считает Folio в domain/bits.jsx.
На сервере seed-проводок в books KV нет полностью.
Нужно одно из:
  (A) расширить seed-catalog / pdf-context seed-проводками как в domain, ИЛИ
  (B) принимать снимок folio с клиента через POST (хуже для аудита), ИЛИ
  (C) писать полный ledger в KV при flush (большая перестройка).
Рекомендация ТЗ: вариант (A) для учебного дома + overlay из
salam-residences-books (payments/utilities) и cards.

API
---
GET /api/pdf/folio/:unitCode
  auth: requirePdfAuth
  404 если нет активного stay
  filename: folio-SR-201.pdf

Билдер
------
buildFolioPdf(doc, ctx) в db/pdf-builders.mjs (или pdf-folio.mjs):
  шапка: дом, студия, жилец, период AS_OF
  таблица движений: дата | вид | описание | сумма
  блоки: залог, проживание, коммуналка, оплаты
  итог: начислено / оплачено / к доплате
  пометка «операционный черновик»

UI
--
DetailPages.jsx ApartmentPage: кнопка «Счёт / Folio PDF» рядом с договором
ResidentPage: та же кнопка (опционально в том же PR)

Критерии приёмки
----------------
1. Студия 201 — PDF открывается, суммы читаемы, кириллица ок
2. Студия с дырами в данных — без 500, прочерки
3. Без токена — 401; crew — 403
4. npm test зелёный

УЛУЧШЕНИЕ U2. Сводный отчёт сети (Reports PDF)
Приоритет: средний | Оценка: 1 день
================================================================================

Цель
----
Из ReportsPage.jsx скачать PDF сводки за сутки / неделю / месяц
(те же цифры, что на экране: оплаты, расходы, долги — по текущей логике domain).

API
---
GET /api/pdf/report?span=day|week|month&houseId=optional
  auth: requirePdfAuth
  только lead (и опционально manager своего дома) — уточнить:
  рекомендация: lead — вся сеть; manager — только свой houseId; иначе 403
  filename: report-month-2026-10.pdf

Данные
------
Серверу нужен расчёт, эквивалентный клиентским отчётам.
Варианты:
  (A) вынести чистые функции отчёта в общий модуль без localStorage
  (B) дублировать упрощённый расчёт на сервере из KV + seed
Рекомендация: (A) — меньше расхождения «экран ≠ PDF».

UI
--
ReportsPage.jsx: кнопка «Скачать PDF» у выбран span (сутки/неделя/месяц)

Критерии приёмки
----------------
1. PDF совпадает по ключевым итогам с экраном на демо-дате AS_OF
2. Смена span меняет содержимое файла
3. Auth как у остальных PDF
